# Этап 3. Каналы и запись — план и итоги

Источник: TZ.md, раздел 11, этап 3 (разделы 4.1, 5.2, 5.3, 9, 10). Правила: docs/PRODUCT_RULES.md.

**Готово, когда:** клиент записался через бота, запись в календаре, напоминание пришло.

## Решения (согласовано 2026-11-15, «все да»)

| # | Вопрос | Решение |
|---|---|---|
| 1 | Кто мастер | Любой активный участник бизнеса с рабочими часами (в том числе владелец-одиночка) |

| 3 | Приём сообщений | На сервере — вебхук с секретом в заголовке; на компьютере разработчика — опрос Telegram программой `scripts/channels-dev.mjs` |
| 4 | Согласие | Перед записью бот показывает текст о данных и кнопку «Згоден»; на сайте — галочка. Точный текст — с юристом |
| 5 | Язык бота | Украинский или английский по языку Telegram клиента (uk и ru → украинский) |
| 6 | Отложено | Предоплата, счёт из чата (этап 4), файл из чата на распознавание (этап 5), AI-администратор (решено «сначала без AI»), сделка из диалога (этап 4), Instagram (после Meta) |

Почему так (разбор идеи 2026-11-15): продолжать до конца этапа 3, затем проверить спрос у 30–50 мастеров, прежде чем строить этапы 4–9. Конкурент в той же нише — «Вчасно.Бізнес» (запись и напоминания, есть бесплатный тариф).

## Сделано (2026-11-15)

### 3.1 Услуги, графики, записи
- У услуги — длительность и перерыв после неё (`products.duration_minutes`, `buffer_minutes`).
- `working_hours` — часы мастера по дням недели, интервалы одного дня не пересекаются.
- `bookings` — запись: мастер, услуга, клиент (контрагент), начало, конец, статус (записан, виконано, не прийшов, скасовано), источник (CRM, Telegram, сайт).
- Пересечение записей одного мастера запрещено базой (ограничение исключения), вместе с перерывом после услуги. Отменённая запись время освобождает.
- `free_slots()` — свободное время каждые 15 минут в пределах рабочих часов, по часовому поясу бизнеса.
- Права: записывают все, кроме бухгалтера; графики меняют владелец и менеджер.
- Схема `supabase/schemas/15_booking.sql`, миграция `20261116100000_booking.sql`, 27 тестов базы.

### 3.2 Календарь
- `/#/calendar`: день по мастерам, нажатие на свободное время создаёт запись, на запись — открывает её (перенос, статус, примечание, «Надіслати нагадування»).
- `/#/working-hours`: графики, кнопка «Пн–Пт, 9:00–18:00».
- На «Сьогодні»: «Записи на сьогодні» со ссылкой на календарь.

### 3.3 Каналы и переписка
- `channels` (Telegram, сайт), `channel_secrets` (ключ бота — недоступен из интерфейса), `channel_events` (повторная доставка обрабатывается один раз), `conversations`, `messages`, `reply_templates`.
- Таймер ответа: `waiting_since` ставится, когда клиент написал то, на что бот не ответил сам, и сбрасывается ответом человека.
- `find_or_create_client()` — клиент по номеру телефона (тот же номер — тот же контрагент), `claim_due_reminders()` — напоминания за 24 и за 2 часа, каждое забирается один раз.
- Коннектор `connectors/telegram` (getMe, sendMessage, getUpdates, setWebhook), серверные функции `telegram_connect`, `telegram_webhook`, `channels_poll`, `chat_send`, `booking_reminders`, `widget_api`.
- Схема `16_channels.sql`, миграция `20261116110000_channels.sql`, 21 тест базы.

### 3.4 Запись через бота
- Диалог кнопками: согласие → «Записатися» → услуга → мастер (если их несколько) → день → время → номер телефона кнопкой → «Підтвердити».
- Если время заняли, пока клиент выбирал, бот предлагает другое. Клиент может выбрать только время, которое предложил бот.
- Свободный текст уходит человеку в «Чати»; бот один раз отвечает, что администратор скоро ответит.
- Логика — `supabase/functions/_shared/bot/bookingFlow.ts`, тексты — `botTexts.ts`, 7 тестов.

### 3.5 Чат-центр
- `/#/chats`: все каналы в одной ленте, фильтры «Усі / Чекають відповіді / Мої», таймер ожидания (красный после 15 минут).
- Диалог: сообщения клиента, бота и сотрудников; ответственный; «Картка клієнта» или «Прив'язати до контрагента»; «Закрити»; шаблоны ответов; ответ уходит клиенту в его канал.
- На «Сьогодні» первым блоком — клиенты, которые ждут ответа.

### 3.6 Виджет сайта
- Код для сайта — в «Бізнес → Канали → Віджет сайту»; `public/widget/widget.js` работает на любом сайте (теневой DOM, без влияния на стили сайта), тексты — `public/widget/texts.json`.
- Запись (с согласием) и чат; ответы из CRM появляются на сайте.

### 3.7 Проверка
- Вживую: клиент записался через тестового бота на 19.11 11:15 (весь диалог в «Чатах»), запись в календаре, напоминание отправлено кнопкой из календаря.
- Автотест `e2e/stage3.spec.ts` (запись через виджет сайта → календарь → чат). Запуск: `PLAYWRIGHT_BASE_URL=http://localhost:5173 npx playwright test e2e/stage3.spec.ts --project=chromium`. Из сессии Claude запуск e2e запрещён проектным хуком, сценарий пройден вручную во встроенном браузере.
- Тесты: база 223, серверные функции и интерфейс 595.

## Как запустить каналы на своём компьютере

1. `make start` и `npx supabase functions serve`.
2. `node scripts/channels-dev.mjs` — забирает сообщения ботов каждые 3 секунды и рассылает напоминания раз в минуту. Пока она не запущена, бот молчит.

## Перед запуском на сервере

- Задать `TELEGRAM_WEBHOOK_BASE_URL=https://<project>.supabase.co/functions/v1` в секретах функций, затем переподключить бота — Telegram начнёт слать сообщения на вебхук.
- В Supabase Cron добавить вызов `booking_reminders` раз в 5 минут с ключом service role.

## Известные ограничения и хвосты

- Клиент не может сам отменить или перенести запись в боте — пишет в чат, администратор меняет в календаре.
- Напоминания только в Telegram; клиент, записавшийся на сайте, их не получает (SMS — отдельным коннектором позже).
- Отправка файлов в чат и приём файлов на распознавание — этап 5.
- Ответственный в диалоге выбирается из всех участников; уведомлений сотруднику о новом сообщении пока нет.
- Буфер записи считается от услуги; разные длительности у разных мастеров — позже.
- Локально Docker однажды перестал пускать к базе по порту 54322; миграции применялись внутри контейнера. Если `npx supabase migration up` выдаёт ошибку подключения — перезапустить Docker Desktop.
